## 1. 项目背景

MoreAni（又看一集）是一个给朋友们用的番剧评分网站。当前 v1.0 已实现核心功能但存在架构问题，需要进行产品化重设计和工程化重构。

### 1.1 当前环境

| 环境 | 位置 | 用途 |
|------|------|------|
| **开发环境** | Windows 本地 (WSL2) | 代码编写、调试、构建 |
| **正式环境** | NAS (192.168.31.26) | 线上运行、用户访问 |

### 1.2 技术栈

- **前端**: Vue 3 + TypeScript + Vite + Tailwind CSS + Element Plus
- **后端**: Python FastAPI + SQLAlchemy + SQLite
- **部署**: Docker + Cloudflare Tunnel
- **域名**: moreani.lovelysia.top

## 3. 用户画像

### 3.1 目标用户

**核心用户**: 主人的朋友们（5-10人小圈子）

| 特征 | 描述 |
|------|------|
| 人数 | 5-10人 |
| 关系 | 朋友，有共同追番兴趣 |
| 使用场景 | 手机/电脑浏览器访问 |
| 使用频率 | 每周几次 |
| 技术水平 | 普通用户，不需要复杂操作 |

### 3.2 使用场景

1. **看完一部番** → 打开 MoreAni → 评分 + 写评论
2. **想找番看** → 打开首页 → 看「大家在看啥」/ 随机推荐
3. **管理片单** → 搜索 + 添加番剧 → 标记想看/在看/看完
4. **查看朋友评价** → 番剧详情 → 看其他人的评分和评论

## 4. 核心问题分析

### 4.1 产品层面

| 问题 | 影响 | 优先级 |
|------|------|:------:|
| 没有观看状态管理 | 用户无法标记「想看/在看/看完」 | P0 |
| 没有用户个人主页 | 无法查看个人评分历史 | P1 |
| 没有社交互动 | 不能评论/点赞朋友的评分 | P2 |
| 没有数据可视化 | 看不到评分分布、观看统计 | P2 |
| 搜索体验一般 | 只能搜标题，不能搜标签/描述 | P1 |

### 4.2 技术层面

| 问题 | 影响 | 优先级 |
|------|------|:------:|
| 单页面 1000+ 行 | 难维护、难调试 | P0 |
| 没有路由 | 所有功能挤在一个页面 | P0 |
| 没有状态管理 | props/emit 层层传递 | P0 |
| 没有测试 | 改一处怕崩全局 | P1 |
| 后端无 service 层 | 业务逻辑和路由混在一起 | P1 |
| 没有 API 版本 | 无法做向后兼容 | P2 |
| 没有 AGENTS.md | LLM 协作无规范 | P1 |

### 4.3 工程层面

| 问题 | 影响 | 优先级 |
|------|------|:------:|
| 无 CI/CD | 手动构建部署 | P1 |
| 无分支策略 | 直接在 dev 上改 | P1 |
| 文档缺失 | 只有 README 和 skill | P2 |
| 无版本管理 | CHANGELOG 不规范 | P2 |

## 5. 功能优先级矩阵

### 5.1 MVP（必须有）

| # | 功能 | 理由 |
|---|------|------|
| 1 | 观看状态管理 | 核心体验，用户需要标记想看/在看/看完 |
| 2 | 前端路由拆分 | 工程化基础，不拆没法迭代 |
| 3 | Pinia 状态管理 | 解耦组件，统一数据流 |
| 4 | 后端 service 层 | 业务逻辑分离，可测试 |
| 5 | 数据库 schema 优化 | 标签关联表、观看状态、软删除 |

### 5.2 v2.1（应该有）

| # | 功能 | 理由 |
|---|------|------|
| 6 | 用户个人主页 | 查看自己的评分历史和统计 |
| 7 | 搜索增强 | 标签搜索、描述搜索 |
| 8 | 单元测试 | 后端 API 测试 + 前端组件测试 |
| 9 | AGENTS.md | LLM 协作规范 |
| 10 | CI/CD | 自动化测试和部署 |

### 5.3 v2.2（可以有）

| # | 功能 | 理由 |
|---|------|------|
| 11 | 社交互动 | 评论点赞 |
| 12 | 数据可视化 | 评分分布图、观看统计 |
| 13 | 通知系统 | 朋友评分通知 |
| 14 | 暗色模式 | UI 扩展 |

## 6. 关键假设（需确认）

在进入设计阶段前，需要确认以下假设：

| # | 假设 | 选项 | 状态 |
|---|------|------|:----:|
| 1 | 产品定位是工具还是社交？ | 纯工具 / 轻社交 / 重社交 | ☐ |
| 2 | 是否需要用户头像？ | 需要 / 不需要 | ☐ |
| 3 | 是否需要番剧分类（类型/年份）？ | 需要 / 不需要 | ☐ |
| 4 | 评分是否需要更细粒度？ | 1-10 / 1-5 / 保持现状 | ☐ |
| 5 | 是否需要番剧状态（想看/在看/看完）？ | 需要 / 不需要 | ☐ |
| 6 | UI 风格保持粉紫还是重新设计？ | 保持 / 微调 / 重设计 | ☐ |
| 7 | 是否需要暗色模式？ | 需要 / 不需要 | ☐ |
| 8 | 数据库是否从 SQLite 迁移到 PostgreSQL？ | 是 / 否 | ☐ |
